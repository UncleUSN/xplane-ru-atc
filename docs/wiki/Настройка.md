# Настройка

Файл — `config.yaml` рядом с `RU-ATC.exe` (или в корне исходников). Установщик создаёт его из `config.example.yaml`. Комментарии в образце можно править. Пути с обратной косой в кавычках лучше писать через прямой слэш: `"D:/X-Plane 12"`.

После правки программу нужно перезапустить.

## Позывной и запасной план

```yaml
callsign:
  spoken: Аэрофлот
  number: "1234"
flight_plan:
  departure: UUEE
  arrival: ULLI
  cruise_fl: 330
```

Если FMC Zibo отдал план, он важнее этого блока, пока пилот сам не назвался в эфире. Без плана диспетчер работает по `flight_plan`. Таблица `airlines` переводит код из номера рейса (`AFL1234` → «Аэрофлот 1234», `SBI213` → «Сибирь 213»).

Первая радиопередача с телефонным позывным компании и номером рейса задаёт обращение на весь полёт. Пример: «Диспетчер, Сибирь 213, здравствуйте» — дальше диспетчер говорит «Сибирь 213», даже если в FMC был другой рейс. Номер можно произнести цифрами или словами: «двести тринадцать», «два один три». Понимаются Аэрофлот, Сибирь, Россия, Победа, Уральские, ЮТэйр, Нордвинд, Азимут, Смартавиа, Ред Вингс и другие компании из `airlines`, а также регистрация вида «RA 73123» / «эр а 73123». Позывной виден в строке «Позывной» окна (пометка «эфир», «FMC» или «config») и пишется в журнал. Если позже назвать другой борт, программа не переключается молча: в журнале будет «в эфире назван …, продолжаем …», а диспетчер по-прежнему зовёт тот позывной, что принял первым.

## Связь с X-Plane

```yaml
sim:
  source: webapi      # webapi | udp | mock
  host: localhost
  webapi_port: 8086
  webapi_version: auto
  use_zibo_datarefs: true
```

`host` — компьютер, где запущен X-Plane. Для второго ПК в сети укажите его IP. Порт должен совпадать с симулятором, по умолчанию 8086.

Вы «на связи» с органом, на частоту которого настроен **активный COM1**. На чужой частоте ответа нет, в окне будет подсказка. Отключить проверку: `atc.strict_frequency: false`.

## Автонастройка COM1

`radio.auto_tune_com1` по умолчанию `false`: частоту ставит пилот, диспетчер по-прежнему отвечает только если активный COM1 на его частоте.

`true` (или галка «Авто COM1» в окне, она действует до закрытия программы и в файл сама не пишется): когда диспетчер говорит «работайте с … на …», программа записывает эту частоту в **резерв** COM1 и меняет его с активной.

* Dataref: `sim/cockpit2/radios/actuators/com1_standby_frequency_hz_833`, затем активный `com1_frequency_hz_833`. Число — килогерцы, как отдаёт X-Plane: `121800` это 121.800. В описании dataref стоит hertz, это старая подпись.
* Обмен: команда `sim/radios/com1_standy_flip` (в имени нет буквы b — так она называется в X-Plane). Команды есть в Web API с версии v2. Если команды нет, активная частота пишется напрямую.
* Zibo 737 читает эти штатные dataref кабины. Отдельный dataref `laminar/B738/...` для COM1 программа не пишет.
* Канал Web API — `PATCH /api/vN/datarefs/{id}/value`. Запасной UDP шлёт пакеты `DREF` и `CMND` на порт X-Plane.
* Пока галка выключена, ничего из этого не происходит.

В симуляторе стоит убедиться, что у Zibo после передачи активная частота COM1 действительно сменилась, а прежняя ушла в резерв. Если панель радиостанции не двигается, откройте Data Ref Editor на этих двух dataref.

## АТИС

Частота АТИС берётся из ряда 1050 `apt.dat` (в кэше навигации это вид `atis`). Пока кэша нет, для Шереметьево и Пулково в `data/airports.yaml` записан образец `atis_freq` — его заменит кэш, как только он собран.

Если активный COM1 стоит на частоте АТИС, программа сама читает сводку на русском: буква информации, рабочая ВПП, ветер, видимость, облачность, температура и точка росы, QNH в гектопаскалях и QFE в миллиметрах, эшелон перехода. Ту же сводку можно запросить: «дайте АТИС», «прослушайте информацию», «запросите информацию».

Буква начинается с «альфа» и меняется по кругу, когда меняется погода или наступает следующий местный час. Повтор той же буквы сам не звучит чаще чем раз в три минуты; просьба пилота включает сводку сразу.

«Информацию Альфа получил» принимается. Если буква не та, диспетчер поправляет: «информация Браво, не Альфа». Пока пилот букву не назвал, диспетчер добавляет её к разрешению и к ответу на выход на связь. В окне строка «АТИС».

Погода:

* у самолёта — dataref `sim/weather/aircraft/` (ветер, QNH, `visibility_reported_m`, `temperature_ambient_c`, `dewpoint_deg_c`, три слоя `cloud_coverage_percent` и `cloud_base_msl_m`). Если точка росы есть только в `sim/weather/region/dewpoint_deg_c[0]`, берётся она. Нет dataref в этой сборке X-Plane — строка сводки пропускается, полёт не останавливается;
* для другого аэродрома — строка этого ICAO в `Output/real weather/METAR.rwx` (или `METAR.rwx` в корне X-Plane). Это сводка, которую сим уже скачал для реальной погоды, не отдельный запрос в интернет.

QFE считается из QNH и превышения: 27.3 фута на 1 гПа, затем в миллиметры ртутного столба.

«Сообщите погоду», «фактическую погоду в Пулково», «погоду на аэродроме назначения» или «на вылете» — диспетчер читает ту же сводку без буквы АТИС. Назначение и вылет берутся из плана (FMC, если он есть). Названный аэродром — если он есть в данных. Далеко от поля и без строки в `METAR.rwx` диспетчер прямо говорит, что это погода у самолёта, а не сводка того аэродрома.

## Бедствие и срочность

«МЭЙДЭЙ МЭЙДЭЙ МЭЙДЭЙ» (достаточно и одного «мэйдэй»: распознаватель часто глотает повтор) — диспетчер принимает бедствие, даёт приоритет, спрашивает намерения, людей на борту и остаток топлива, называет ближайший подходящий аэродром, ВПП, удаление и курс и предлагает ответчик 7700. «Пан-пан» — срочность, приоритет ниже бедствия.

Пока бедствие, срочность или отказ радиосвязи не сняты, приветствия и прощания не добавляются.

Ответчик 7700 в симуляторе сам объявляет бедствие, 7600 — отказ радиосвязи («если слышите, продолжайте по последнему разрешению»). Код, который поставил пилот, снимается, когда на приборе уже не 7700 и не 7600. Бедствие, сказанное голосом, снимается только фразой: «отменяю бедствие», «отбой мэйдэй», «ситуация нормальная», «отбой пан-пан». Если 7700 ещё горит, диспетчер просит вернуть назначенный код.

Назначенный код при 7700 или 7600 не оспаривается.

## Строгость readback

`atc.readback_strictness`

* **lenient** (так и записано установщиком, и так же, если ключа в старом файле нет). Закрывают указание: «подтверждаю», «подтверждаю приём», «понял», «принял», «выполняю», «вас понял», «так точно», «роджер», «уилко». Можно с позывным: «пятьсот первый» — это 501. Мелкие ошибки распознавания вроде «подтвреждаю», «шереметев», «делились» прощаются. Если в той же фразе названа неверная ВПП, эшелон, код или частота, диспетчер поправит. Одну и ту же просьбу повторить он задаёт не больше двух раз, затем сам называет значения и идёт дальше.
* **strict**. Нужно повторить сами значения. Голое «понял» указание не закроет.

Рядом: `atc.readback_timeout_s` (по умолчанию 20 секунд, затем «подтвердите приём») и `atc.confirm_correct_readback` («правильно» после верного повтора).

«Добрый день», «здравствуйте», «до свидания», «спасибо», «всего доброго» и «хорошего дня» можно сказать в любой части фразы, отдельно или вместе с просьбой и подтверждением. Разрешение от этого не открывается заново. Одно «спасибо» или «до свидания» после передачи не вызывает «повторите»: диспетчер коротко ответит или промолчит. Чужие цифры по-прежнему поправляются: «подтверждаю, ответчик семь семь семь семь» останется ошибкой, даже если рядом «добрый день».

## Приветствия

`atc.chattiness`

* **normal** — так и записано, и так же, если ключа в старом файле нет. При первом выходе на каждый орган диспетчер иногда добавляет приветствие, при смене частоты — прощание. Не в каждой реплике.
* **high** — почти всегда.
* **off** — как раньше: только фразеология, без «доброе утро» и «счастливого полёта». Пилот при этом всё равно может здороваться и прощаться, «повторите» на это не будет.

```yaml
atc:
  chattiness: "normal"   # "off" | "normal" | "high"
```

Кавычки нужны: голое `off` в YAML некоторые программы читают как «выключено» в смысле логического значения, а не как слово.

Приветствие зависит от местного времени в симуляторе (dataref `sim/time/local_time_sec`):

| Часы | Пример |
| --- | --- |
| 5–11 | доброе утро, иногда здравствуйте |
| 12–16 | добрый день |
| 17–22 | добрый вечер |
| 23–4 | здравствуйте |

Если dataref нет, берутся часы компьютера.

Прощание при передаче: «до свидания», «счастливого пути», «счастливого полёта», «всего доброго», «хорошего дня», иногда «принято, хорошего полёта». На заходе и в разрешении посадки может быть «мягкой посадки». Добавка стоит после позывного или в конце фразы. Разрешение, частота, высота, код ответчика и ВПП остаются на своих местах и по-прежнему проверяются при повторе.

Пример, утро в симуляторе:

```text
Вы: Шереметьево-Деливери, Аэрофлот 1234, доброе утро, прошу разрешение до Пулково
Диспетчер: Аэрофлот 1234, доброе утро, Шереметьево-Деливери, разрешено до Пулково, … ответчик …
Вы: подтверждаю приём, спасибо
Диспетчер: Аэрофлот 1234, правильно, … работайте с Шереметьево-Руление …, счастливого полёта
Вы: до свидания
Диспетчер: Аэрофлот 1234, до свидания
```

Последняя реплика диспетчера может и не прозвучать. Это не ошибка распознавания.

## Окно и горячие клавиши

```yaml
ui:
  always_on_top: true
  topmost_reassert_s: 2.0
  start_compact: false
  compact_alpha: 0.85
  compact_geometry: "560x180-20+40"
  full_geometry: "1100x680"
  compact_borderless: true
  hotkey_toggle: "ctrl+shift+a"
  hotkey_compact: "ctrl+shift+z"
  focus_on_show: false
```

* `always_on_top` держит окно над другими. Раз в `topmost_reassert_s` секунд программа поднимает его снова, не забирая фокус у X-Plane. В эксклюзивном полноэкранном режиме это не работает, нужен оконный или безрамочный режим симулятора. Переключатель «Поверх всех» есть и в окне.
* Компактная панель: кнопка «Компактно», ключ запуска `--compact` или `start_compact: true`. На ней фаза, орган, разрешение, код, **последние 5 реплик** (диспетчер бирюзовым, пилот жёлтым, новые снизу) и индикатор тангенты. Панель без рамки перетаскивается мышью. Двойной щелчок или «⤢» возвращает полный вид, «—» прячет окно.
* `compact_geometry: "560x180-20+40"` — ширина, высота, 20 пикселей от правого края и 40 от верха.
* `hotkey_toggle` показывает и прячет окно, в том числе свёрнутое. `hotkey_compact` переключает компактный и полный вид. Пустая строка клавишу выключает. Сочетание не должно быть занято в X-Plane.
* `focus_on_show: false` после показа возвращает фокус симулятору. `true` оставляет фокус в окне, чтобы сразу печатать фразу.

## Папка X-Plane и навигация

```yaml
flight_plan_import:
  xplane_path: "D:/X-Plane 12"   # установщик пишет сам
navdata:
  provider: xplane               # xplane | navigraph | off
  xplane_path: ""                # пусто = путь из flight_plan_import
  cache_dir: ""
  corridor_km: 50
  rebuild: false
```

`provider: navigraph` ничего не скачивает: подписки в программе нет. `off` оставляет только учебные yaml.

Пустая строка в одном ключе берёт другой. Оба пустые — автопоиск. Свой `navdata.xplane_path` важнее для частот и схем, свой `flight_plan_import.xplane_path` важнее для папки `Output/FMS plans`. Как устроен кэш, какие файлы читаются и что смотреть в журнале — в [[Навигационные данные|навигационных данных]].

## Папка планов FMS

```yaml
flight_plan_import:
  source: auto          # auto | fmc | fms | config
  xplane_path: ""       # например "D:/X-Plane 12"
  fms_max_age_h: 12
  fmc_side: 1           # 1 — CDU командира, 2 — второго пилота
  poll_s: 2.0
  callsign_from_fmc: true
```

`xplane_path` — папка установки X-Plane 12. Планы ищутся в `Output/FMS plans` внутри неё. Пустая строка включает автопоиск: `%LOCALAPPDATA%\x-plane_install_12.txt` (в том числе если файл в UTF-16), типичные пути (`C:/X-Plane 12`, `D:/X-Plane 12`, Steam) и, если задан, `navdata.xplane_path`. Если папка не найдена, в журнал пишется, что именно проверялось: нет пути, это не корень X-Plane, или корень есть, но каталога планов ещё нет. Что делать дальше — в [[Устранение неполадок|устранении неполадок]]. Как план попадает диспетчеру — в [[План полёта|плане полёта]].

## Тангента и звук

```yaml
voice:
  enabled: true
  ptt_key: "caps lock"          # или "right ctrl", "f12"
  ptt_joystick: null            # {device: 0, button: 5}
  input_device: null            # null, номер или часть имени: "acer"
  output_device: null
  host_api: null                # WASAPI | MME | DirectSound
  radio_effect: true
  radio_noise: 0.015
```

Удерживайте клавишу, говорите, отпустите. В окне есть кнопка «Тангента» и поле текста — ими удобно проверить фразеологию без микрофона.

`input_device: null` — устройство записи Windows по умолчанию. Если гарнитур несколько, укажите кусок имени. Одно устройство Windows показывает отдельно для каждого звукового API; `host_api: MME` обычно самый совместимый.

Список устройств из исходников: `python tools/mictest.py --list`.
