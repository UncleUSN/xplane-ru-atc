# План полёта

Программа подхватывает маршрут из FMC Zibo и перечитывает его каждые `flight_plan_import.poll_s` секунд (по умолчанию 2). Сменили ВПП или схему — диспетчер берёт новые данные. Если плана нет, работает `flight_plan` из config.

Режим `source`:

* `auto` — datarefs FMS, экран CDU и файл `.fms`;
* `fmc` — только FMC;
* `fms` — только файл;
* `config` — импорт выключен.

В UDP строки передать нельзя, поэтому там остаётся только `.fms`. В `--demo` и `mock` импорт выключен.

## Откуда берутся поля

1. **Datarefs FMS** `laminar/B738/fms/*` и `laminar/B738/FMS/*` — основной маршрут, листать CDU не нужно.
   * Аэропорты и ВПП: `ref_icao`, `ref_runway`, `dest_icao`, `dest_runway`. Запасная пара — `flight09`, строка вида `UUEE - ULLI`.
   * Точки: `legs` (имена через пробел), `legs_lat` / `legs_lon`, `num_of_wpts`, `legs_pth` (тип участка, два символа: TF, DF, IF, CF, CI, HM…).
   * Из списка убираются аэропорты, ВПП (`RWxx`), перехваты `(INTC)`, точка захода `FFxx` и всё после ВПП назначения — это уход на второй круг.
   * Длина маршрута: `fpln_dist`, остаток до назначения: `dist_dest` (морские мили).
   * `fmc_gw_app` — число, не имя захода. Программа его не использует. Пока на странице прибытия нет маркера `<SEL>` или `<ACT>`, заход пустой. ВПП посадки при этом видна по `dest_runway` и участкам `FFxx` / `RWxx`.
2. **Экран CDU** через Web API. Zibo публикует строки как текст (`laminar/B738/fmc1/Line00_L`, `Line01_X`, `Line01_L`, `Line01_S`…). Слои строки накладываются по колонкам: берётся первый непустой символ. Символ `` ` `` на экране — градус. Страница узнаётся по заголовку.
   * **PERF INIT**: крейсерский эшелон из `TRIP/CRZ ALT` (`FL410/FL330` → FL330).
   * **RTE 1**: ORIGIN, DEST, RUNWAY, номер рейса. Точки с этой страницы — только если списка `legs` нет.
   * **DEP/ARR**: SID, STAR, заход и переходы — только пункт с `<SEL>` или `<ACT>` рядом с именем. Строка из списка `UUEE DEPARTURES 1/10` без маркера — доступная схема, не выбранная.
   * **LEGS** на экране — запасной список точек, если dataref `legs` недоступен.

   Эшелон и схемы видны, только когда открыта нужная страница. Аэропорты, ВПП и точки приходят из datarefs и без листания. Сторона CDU: `fmc_side` 1 или 2.
3. **Файл `.fms`** из `<X-Plane 12>/Output/FMS plans`, формат v1100: ADEP/ADES, ВПП, SID/STAR с переходами, заход, точки с координатами. Берётся самый свежий файл с теми же ORIGIN и DEST, что в FMC. Если FMC ещё пуст — самый свежий не старше `fms_max_age_h` часов. Точки из файла не подменяют живой список `legs`.

   Файл появляется, если сохранить маршрут в Zibo (RTE, страница 1, имя в блокноте, **SAVE ROUTE**; в EFB нужен формат **FMS**, не FMX) или загрузить CO ROUTE из готового `.fms`.

   Папка X-Plane — `flight_plan_import.xplane_path`. Если её нет, программа ищет сама. Сообщение об ошибке содержит проверенный путь. См. [[Устранение неполадок|устранение неполадок]].
4. **config.yaml** закрывает только те поля, которые FMC и файл не дали, и только для тех же аэродромов.

## Что слышно в эфире

* Аэродром вылета меняется по FMC, пока вы на земле, назначения — до разрешения на заход. Если аэродрома нет в `data/airports.yaml`, но в `.fms` есть координаты и ВПП, его заводит РЦ без своих органов. Иначе остаётся аэродром из config, и в окне будет предупреждение.
* Разрешение называет ВПП, схему и переход, если они выбраны: «взлёт ВПП 24 центральная, выход по схеме лаки один гольф с переходом лакиб, набор 6000 футов». Нет схемы — «выход по схеме согласно плану».
* Набор до крейсерского эшелона берётся из CRZ ALT.
* Снижение: «снижайтесь до эшелона 150, ожидайте прибытие по схеме …». Подход называет тип захода из имени в FMC (`ILS28R`, `RNV28R`, `I28R`).
* Точка начала снижения считается по остатку пути вдоль маршрута, если у точек есть координаты. Иначе берётся `dist_dest`, иначе прямая до аэродрома.
* Позывной: `AFL1234` → «Аэрофлот 1234» по таблице `airlines`. Выключается `callsign_from_fmc: false`.
* Передачи между секторами РЦ идут по фактическому положению самолёта, не по строке плана.
* В окне строка вида «План FMC: UUEE ВПП 24C … → ULLI …».

## Диагностика

Из исходников: `python tools/fmcdump.py`. Утилита показывает экран CDU, строковые datarefs, значения `laminar/B738/fms/*`, файлы `.fms` и итоговый план. `--watch 60` следит за CDU минуту, пока вы листаете страницы. Отчёт — `logs/fmcdump_*.txt`.
