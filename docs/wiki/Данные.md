# Данные

С 0.3.0-beta частоты органов, ВПП, схемы и секторы РЦ по возможности берутся из файлов X-Plane. Как устроены кэш, путь и пересборка — в [[Навигационные данные|навигационных данных]]. Файлы `data/airports.yaml` и `data/airspace.yaml` остаются запасом: русские позывные, высоты перехода, коды ответчика и предпочтительные ВПП. Для настоящей навигации они не годятся.

| Что | Как проверялось |
| --- | --- |
| Web API X-Plane (адреса, подписка, обновления) | по документации developer.x-plane.com и тестом с поддельным сервером |
| UDP RREF | известный формат пакетов, юнит-тесты; на живом X-Plane в этой бете не гонялся |
| Datarefs `sim/...` | сверены с официальным `DataRefs.txt` X-Plane 12 |
| `com1_frequency_hz_833` | в описании «hertz», на практике значение часто в кГц (118700). Программа понимает оба |
| Zibo `laminar/B738/...` | публичные списки (B738_Datarefs.txt релиз 2.35, форум, скрипты FlyWithLua). В новой версии Zibo имена могут съехать. Положения ответчика 1 = STBY и 5 = TA/RA подтверждены, остальные предположены |
| Москва, высота и эшелон перехода | учебные значения. С 03.12.2020 ниже эшелона перехода в РФ футы и QNH. Порог QNH сверьте сами, если строите свой сценарий |
| Пулково, высоты перехода | по открытым сводкам, не по актуальному AIP |
| Частоты UUEE, UUDD, UUWW, ULLI | из `apt.dat` / `atc.dat` вашей установки X-Plane, если кэш собрался. Иначе карточки IVAO и старые выписки из yaml |
| Границы Москва-Контроль и Санкт-Петербург Контроль | из `atc.dat`, если полигон центра накрывает точку. X-Plane не хранит отдельные секторы внутри органа. Нет полигона — заглушка, грубый прямоугольник из yaml |
| Региональные аэродромы | примерные координаты и ВПП, без своих частот: работает РЦ |
| Фразеология | близко к практике и к порядку радиосвязи, но упрощена. Шаблоны в `controller.py` |
| 250 узлов ниже 10 000 футов | учебная проверка, выключается `atc.speed_limit_kt: 0` |

Свои аэропорты добавляются правкой yaml в папке `data` рядом с программой. После правки нужен перезапуск.
